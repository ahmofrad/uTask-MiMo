# i18n.md — Persian + English, RTL, Jalali Calendar

> How `fa-IR` and `en-US` fit together. Read this before implementing Phase 8.

---

## 1. Goals

- **Persian (`fa-IR`) is the default locale.** All UI, all dates, all numbers render in Persian out of the box for new users.
- **English (`en-US`) is a first-class secondary locale.** Switching should be instant, no reload.
- **RTL is the default direction for `fa-IR`.** Layouts must work correctly mirrored.
- **Jalali (Solar Hijri) calendar is the default for `fa-IR`.** Gregorian available per-user toggle.
- **No hardcoded strings** anywhere in the component tree.
- **Translations are first-class artifacts.** CI fails on missing `fa-IR` translations.

---

## 2. Library Choice: `next-intl`

Why `next-intl` over alternatives:

- **SSR-friendly** — translations ship with the initial HTML, no flash of untranslated content.
- **App Router native** — works with `[locale]` segments.
- **ICU MessageFormat** — handles plurals, gender, select, number/date formatting in one syntax.
- **Tree-shakable** — only the namespaces actually used ship to the client.
- **Type-safe keys** — TypeScript catches typos in `useTranslations('key')`.

Alternatives considered:
- `react-i18next` — strong but App Router SSR story is worse; heavier client bundle.
- `next-translate` — simpler but less powerful formatting.
- LinguiJS — powerful but the macro syntax adds a build step the AI agent might mishandle.

## 3. Locale Routing

### 3.1 URL structure

- Default locale `fa-IR` is **not** in the URL: `/dashboard` → `fa-IR`.
- Non-default locales get a prefix: `/en-US/dashboard`.

Implementation via `[locale]` dynamic segment in `src/app/[locale]/` plus middleware:

```ts
// middleware.ts (sketch)
import createMiddleware from 'next-intl/middleware';

export default createMiddleware({
  locales: ['fa-IR', 'en-US'],
  defaultLocale: 'fa-IR',
  localePrefix: 'as-needed', // fa-IR: no prefix; en-US: /en-US prefix
  localeDetection: true,     // respect Accept-Language header
});

export const config = {
  matcher: ['/((?!api|_next|_vercel|.*\\..*).*)']
};
```

### 3.2 Locale detection order

1. URL prefix.
2. `NEXT_LOCALE` cookie (set by user preference).
3. `Accept-Language` header.
4. Default: `fa-IR`.

### 3.3 Per-user preference

Stored in `User.locale`. On login, set the `NEXT_LOCALE` cookie to match. After login, a language switcher in the header updates the cookie and reloads.

### 4.2 Pluralization

ICU handles this:

```json
{
  "task": {
    "dueIn": "{count, plural, one {فردا} other {در {count} روز آینده}}",
    "overdueBy": "{count, plural, one {دیروز} other {از {count} روز پیش}}"
  }
}
```

### 4.3 Interpolation

```json
{
  "task": {
    "assignedTo": "اختصاص داده شد به {name}",
    "dueAt": "سررسید: {date}"
  }
}
```

### 4.4 Date interpolation (avoid; use components)

Don't pass formatted dates through translation keys. Format in the locale's formatter and pass as `date={formattedDate}`:

```tsx
// Good:
t('task.assignedTo', { name: user.displayName })
t('task.dueAt', { date: formatDate(task.dueDate, locale) })

// Bad:
t('task.dueAt', { date: task.dueDate.toLocaleDateString() })  // never
```

## 5. CI Enforcement

Two scripts in `package.json`:

```json
{
  "scripts": {
    "i18n:extract": "i18next-parser 'src/**/*.{ts,tsx}' --output src/messages/$LOCALE.json",
    "i18n:check": "ts-node scripts/i18n-check.ts"
  }
}
```

`i18n-check.ts`:

```ts
// Pseudocode
// 1. Parse both JSON files.
// 2. Find keys in en-US that are missing in fa-IR → fail with list.
// 3. Optionally: check for untranslated keys (value === key) → fail.
// 4. Optionally: detect hardcoded strings via regex scan of JSX (best-effort).
```

CI runs `pnpm i18n:check` after `pnpm typecheck`. Build fails if `fa-IR` is incomplete.

**Optional:** add `eslint-plugin-i18next` to lint components for hardcoded strings.

## 6. RTL Support

### 6.1 Logical CSS properties

**Never** use physical properties. Always logical:

| ❌ Avoid | ✅ Use |
|---------|-------|
| `ml-2`, `mr-2` | `ms-2`, `me-2` |
| `pl-4`, `pr-4` | `ps-4`, `pe-4` |
| `left-0`, `right-0` | `start-0`, `end-0` |
| `text-left`, `text-right` | `text-start`, `text-end` |
| `border-l`, `border-r` | `border-s`, `border-e` |

Tailwind 3.4+ supports logical properties natively.

### 6.2 `<html dir="...">`

Set in the root layout per locale:

```tsx
// src/app/[locale]/layout.tsx
export default function LocaleLayout({ children, params: { locale } }) {
  return (
    <html lang={locale} dir={locale === 'fa-IR' ? 'rtl' : 'ltr'}>
      ...
    </html>
  );
}
```

### 6.3 Icons that should mirror

Some icons imply direction (chevron, arrow). Mirror them in RTL via `[dir='rtl'] &` selector or `transform: scaleX(-1)`.

Maintain an allowlist in `components/icons/mirror.ts`:

```ts
export const MIRRORED_ICONS = new Set([
  'ChevronLeft', 'ChevronRight', 'ArrowLeft', 'ArrowRight',
  'PanelLeft', 'PanelRight', 'Send', 'Reply'
]);
```

In the icon component:

```tsx
const shouldMirror = MIRRORED_ICONS.has(name) && dir === 'rtl';
return <Icon style={shouldMirror ? { transform: 'scaleX(-1)' } : undefined} />
```

### 6.4 Components that need a "rtl" prop

Date pickers, dropdowns, tooltips, modals — anything with positioning logic — must read `dir` from context or pass it through. Use the `useLocale()` hook from `next-intl` (gives direction + locale).

### 6.5 Fonts

- `fa-IR`: `Vazirmatn` or `IranSans` — open-source, designed for Persian.
- `en-US`: `Inter` or system stack.
- Use `next/font` to self-host (no Google Fonts CDN = no outbound traffic).

### 6.6 Testing RTL

- Playwright tests must include one run per major route with `locale: 'fa-IR'`.
- Manual checklist for every new layout:
  - [ ] Sidebar position (right in RTL).
  - [ ] Icon directions mirror correctly.
  - [ ] Text alignment is start-aligned.
  - [ ] Form labels are right of inputs.
  - [ ] No horizontal scrollbar.
  - [ ] Modals center correctly.
  - [ ] Dropdowns align to their trigger correctly.

## 7. Jalali Calendar

### 7.1 Library

`date-fns-jalali` — drop-in companion to `date-fns`, tree-shakable.

```ts
import { format } from 'date-fns';
import { format as formatJalali } from 'date-fns-jalali';
import { faIR } from 'date-fns/locale';
import { faIR as faIRJalali } from 'date-fns-jalali/locale';

format(new Date(), 'PPP', { locale: faIR });           // Gregorian, Persian month names
formatJalali(new Date(), 'PPP', { locale: faIRJalali }); // Jalali, Persian month names
```

### 7.2 Helper module

`src/lib/date/format.ts`:

```ts
import { format as formatGregorian } from 'date-fns';
import { format as formatJalali } from 'date-fns-jalali';
import { enUS, faIR } from 'date-fns/locale';
import { faIR as faIRJalali } from 'date-fns-jalali/locale';

export function formatDate(
  date: Date,
  locale: 'fa-IR' | 'en-US',
  calendar: 'jalali' | 'gregorian',
): string {
  if (locale === 'fa-IR' && calendar === 'jalali') {
    return formatJalali(date, 'PPP', { locale: faIRJalali });
  }
  if (locale === 'fa-IR' && calendar === 'gregorian') {
    return formatGregorian(date, 'PPP', { locale: faIR });
  }
  return formatGregorian(date, 'PPP', { locale: enUS });
}
```

### 7.3 Date picker

Use `react-day-picker` with the `date-fns-jalali` adapter. Component reads `locale` and `calendar` from context.

```tsx
<DayPicker
  mode="single"
  selected={value}
  onSelect={onChange}
  locale={locale === 'fa-IR' && calendar === 'jalali' ? faIRJalali : enUS}
  dir={dir}
/>
```

### 7.4 Default per user

- `User.locale = 'fa-IR'` → calendar default `jalali`, with a toggle to `gregorian` in date pickers (per-picker, not persisted).
- `User.locale = 'en-US'` → calendar always `gregorian`.

The toggle is a UI affordance on the date picker itself ("Show in Gregorian").

## 8. Numbers

### 8.1 Persian numerals

Optional per-user toggle. When enabled, format all numbers with Persian digits:

```ts
const persianDigits = ['۰', '۱', '۲', '۳', '۴', '۵', '۶', '۷', '۸', '۹'];
export function toPersianDigits(input: string | number): string {
  return String(input).replace(/\d/g, (d) => persianDigits[+d]);
}
```

Use `Intl.NumberFormat` with `locale='fa-IR'` and `useGrouping: false` to get Persian digits:

```ts
new Intl.NumberFormat('fa-IR', { useGrouping: false }).format(1234);
// → "۱۲۳۴"
```

### 8.2 Currency

Don't ship with a hardcoded currency. Customer configures in admin settings. Default to no currency display unless set.

### 8.3 Date-time display

```ts
new Intl.DateTimeFormat('fa-IR', {
  year: 'numeric', month: 'long', day: 'numeric',
  hour: '2-digit', minute: '2-digit',
  calendar: 'persian',  // Persian calendar (Jalali)
  numberingSystem: 'arabext',  // Persian-Indic digits
}).format(new Date());
// → "۱۴۰۳ فروردین ۱۵، ساعت ۱۴:۳۰"
```

## 9. Content Considerations

### 9.1 Email templates

Bilingual email templates in `src/lib/mail/templates/`:

- `assigned/fa-IR.html`, `assigned/en-US.html`
- `mentioned/fa-IR.html`, `mentioned/en-US.html`
- `due_soon/fa-IR.html`, `due_soon/en-US.html`
- `daily-digest/fa-IR.html`, `daily-digest/en-US.html`

Each template renders with `next-intl` for in-template strings, plus locale-appropriate date formatting.

### 9.2 Audit log display

Admin's audit log UI shows entries in the admin's chosen locale. The actor's `displayName` is shown as-is.

### 9.3 User-generated content

- Task titles, descriptions, comments are stored as the user typed them (no translation).
- Markdown rendering is the same in both locales.
- `@mention` resolution uses `displayName` (no translation).

### 9.4 Avoid mixing RTL/LTR in strings

Don't mix Persian and English in a single phrase unless using a span with explicit `dir`:

```tsx
// Bad: direction gets confused
<p>ایمیل شما example@corp.com است</p>

// Good: explicit LTR span
<p>
  ایمیل شما <span dir="ltr">example@corp.com</span> است
</p>
```

Create a `<Email>` or `<LtrSpan>` component to make this idiomatic.

## 11. Open Decisions

- **Date picker library** — `react-day-picker` is the current pick. Alternatives: build custom, use `mantine` dates (heavier).
- **Time zone display** — always show in user's local time zone; never show raw UTC. Customer admins may set a default org time zone in settings.
- **First-day-of-week** — `fa-IR`: Saturday (default in `date-fns-jalali` locale). `en-US`: Sunday (default).
- **Translation source** — for now, hand-written. If scale demands, integrate a translation platform (Crowdin, Lokalise) via their CLI in CI.
