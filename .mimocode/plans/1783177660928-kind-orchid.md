# Plan: Fix Critical and High Priority Gaps

## Priority 1: BullMQ workers + email integration
**Why:** Webhooks and emails don't work at all in production.
- Fix `src/instrumentation.ts` to call `startWorkers()` in production mode
- Wire `notifyAssigned()` into task assignment changes in `src/lib/tasks/mutations.ts`
- Fix SMTP settings: `lib/mail/send.ts` should read from DB settings table, falling back to env vars

## Priority 2: Notifications mark-all-as-read + backup API
**Why:** Two buttons in the UI do nothing.
- Wire the "Mark all as read" button in notifications page → POST `/api/v1/notifications/read-all`
- Create `src/app/api/v1/admin/backups/run/route.ts` that calls `scripts/backup.sh`

## Priority 3: Webhook secrets encrypted at rest
**Why:** Security requirement — secrets in plaintext DB.
- Add AES-256-GCM encryption/decryption in `lib/crypto/` for webhook secrets
- Encrypt on create, decrypt on delivery dispatch

## Priority 4: CSRF protection
**Why:** Security gap on state-changing endpoints.
- Add CSRF token middleware that generates/validates tokens for POST/PATCH/DELETE
- Tokens stored in httpOnly cookie, validated from request header

## Priority 5: Idempotency key validation
**Why:** Spec requires it for POST /tasks and POST /comments.
- Create `lib/idempotency/` with Redis-backed key store
- Middleware checks `Idempotency-Key` header on POST endpoints
- Returns cached response if key already processed

## Priority 6: Tags CRUD API
**Why:** Tags can only be created inline with tasks — no management.
- `POST /api/v1/tags` — create tag
- `GET /api/v1/tags` — list tags
- `DELETE /api/v1/tags/:id` — delete tag

## Priority 7: Audit log for remaining mutations
**Why:** Incomplete audit trail.
- Add audit logging to settings updates, department CRUD, SSO config changes

## Priority 8: Notifications mark-all-as-read API
**Why:** Button exists but has no backend.
- `POST /api/v1/notifications/read-all` — mark all notifications as read

- Workers start and process webhook/email jobs
